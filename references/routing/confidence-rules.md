# 置信度与保守处理

[返回总入口](../../SKILL.md) · [信息决策门](../clarification/ambiguity-gate.md) · [输出路由](./output-mode-routing.md)

这里的置信度不是数学分数，只用于决定能否给强判断、是否需要一个补充问题，以及怎样表达不确定性。

## 高置信度

特征：关键事实能相互印证，主导结构和方法入口明确，替代解释不足以改变行动方向。

动作：直接分析或给方案，不额外追问。

## 中置信度

特征：方向基本清楚，但有一个未知项可能改变路线顺序或力度。

动作：

- 给暂定判断和适用条件。
- 写出最重要的替代解释。
- 说明什么信号会改变判断。
- 必要时只补 `1` 个判别问题。

## 低置信度

特征：当前结论主要靠猜，多张方法卡都像能用，或不同解释会导向相反行动。

动作：

- 退回 [ambiguity-gate.md](../clarification/ambiguity-gate.md)。
- 用户允许追问时，补最少信息。
- 用户要求基于现有信息回答时，只给情景化结论，不做强定性。
- 不使用高风险术语，不生成 HTML 来掩盖内容不稳定。

## 方法选择

- 事实和对象混乱：优先 `调查研究`。
- 冲突很多、抓不住重点：优先 `主要矛盾`。
- 旧打法失灵、环境联动变化：优先 `阶段判断`。
- 资源有限、多线竞争：优先 `力量与资源`。
- 多方合作和边界复杂：优先 `关系联结与联盟边界`。
- 判断已有但表达失真：优先 `沟通校准`。
- 方向已有但落不下去：优先 `执行路线`。
- 已有行动结果：优先 `实践检验与复盘`。

两张卡都适用时，选择能最早减少关键不确定性的那张，而不是机械选择“更前置”的卡。

## 风险表达

对 `主要矛盾、统一战线、群众路线、整风、持久战、合法性、统一口径` 等词拿不准时：

1. 先用现代工作语言表达。
2. 再读 [misuse-boundaries.md](../risks/misuse-boundaries.md) 和 [translation-red-lines.md](../risks/translation-red-lines.md)。
3. 无法安全转译就不使用该术语。

## 输出选择

- 用户指定形式时服从用户。
- 用户未指定时默认用最小充分形式。
- 内容不稳定时不要做 HTML。
- 结构复杂且用户明确要 HTML 时，内容稳定后直接生成，不重复确认。

## 推荐表达

```text
基于当前信息，我的暂定判断是……
这个判断依赖两个假设：……
如果出现……，结论需要调整为……
当前最值得先验证的是……
```

不要把置信度写成装饰性百分比，除非有明确、可解释的评分依据。
