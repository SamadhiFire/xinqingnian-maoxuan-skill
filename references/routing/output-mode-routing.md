# 输出模式路由

[返回总入口](../../SKILL.md) · [轮次结构](../clarification/round-response-structure.md) · [HTML 规范](../html-output/visual-report-spec.md)

输出形式服从用户明确要求，不为流程再索取一次已经给出的选择。

## 可用形式

- 简短初判
- 文字版结构分析
- 行动方案
- 自包含 HTML 报告
- 在分析之后附加的话术、邮件或会议表达

这些形式可以组合，不必强制用户只在“深度分析”和“HTML”之间二选一。

## 路由规则

- 用户已明确指定形式：直接采用。
- 用户没指定但任务清楚：默认输出文字版分析或方案，不额外追问格式。
- HTML 会显著增加工作量且用户没提出：先交付文字内容；必要时在结尾说明可继续转成 HTML。
- 用户明确要 HTML：内容判断稳定后直接生成；若关键信息不足，说明缺口并按信息决策门处理。
- 用户要一句回复、邮件或话术：先给完成任务所必需的最小结构判断，再直接给文案；不要强迫用户先走完整报告流程。

## 文字分析骨架

对话中的文字分析先保持三段顶层骨架：

1. 先把情况摆清
2. 再看什么牵住全局
3. 眼下先做什么

下面内容按问题需要放进对应三段，不机械保留所有模块：

1. 问题重述
2. 核心判断与依据
3. 主导结构或阶段
4. 替代解释与不确定性
5. 路线、顺序和边界
6. 观察信号、验证动作和止损条件
7. 方法出处（仅在有帮助或用户要求时）

其中 `问题重述、事实基础` 放入第一段；`核心判断、阶段、替代解释` 放入第二段；`路线、验证、止损和方法出处` 放入第三段或末尾附注。HTML 报告不受三段页面模块数量限制。

## HTML 输出

1. 读取 [visual-report-spec.md](../html-output/visual-report-spec.md)。
2. 读取 [report-build-rules.md](../html-output/report-build-rules.md)。
3. 复制 [visual-report-template.html](../html-output/visual-report-template.html) 到目标文件，不直接修改模板源文件。
4. 删除不需要的模块，替换全部占位内容。
5. 运行 `python scripts/quick_validate.py . --html <目标文件>`。

默认文件名使用 `YYYY-MM-DD-topic.html`，默认写入当前工作目录；用户指定路径时服从用户。

## 出处展示

方法出处可按下面格式轻量呈现：

```text
原文依据：篇名或关键命题
现代转译：本 skill 如何将其转成现代分析方法
本次推断：该方法如何用于当前案例
```

不要暗示“本次案例结论”是原文直接说出的结论。

## 禁止事项

- 不重复询问用户已经明确的输出形式。
- 不把内部分类、场景和文件路由当成报告正文。
- 不为了展示完整而生成空模块或重复模块。
- 不把话术需求无限升级成用户没有要求的长报告。
